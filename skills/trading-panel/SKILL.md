# 交易评审团 (Trading Panel)

移植自 TauricResearch/TradingAgents（Apache-2.0，arXiv 2412.20138）的编排范式，
在 Claude Code 上用 subagent 实现，无需 Python 环境和 API key。

## 不可逾越的三条

1. **不是投资建议**。每次输出必须带免责声明。用户的钱由用户自己决定。
2. **不许代下单**。即使用户要求，也只给分析，不执行任何交易操作。
3. **数据缺失必须明示**。查不到的数据写"无法获取"，绝不用模型记忆里的旧数字冒充实时行情——
   这是这类系统最危险的失真点。

## 流程

### 第 0 步：确定标的与视角

确认三件事：
- **标的**：代码 + 全称（歧义时先澄清，如"小米"是港股 1810 还是别的）
- **分析基准日**：默认今天；用户可指定历史日期做"时间旅行验证"
- **持仓视角**：空仓看是否建仓 / 已持仓看是否加减 / 纯研究。三者的结论口径不同。

### 第 1 步：四路分析师（并发）

用 Agent 工具**一条消息内同时**起四个分析师，各自取证、各自成文，禁止互相引用、禁止下买卖结论：

| 分析师 | 职责 | 必须给出 |
|---|---|---|
| **技术面** | 价格、均线、成交量、动量指标、关键支撑阻力位 | 当前价、趋势判断、具体价位 |
| **基本面** | 营收利润趋势、毛利率、现金流、负债、估值倍数 | 最近几期数字 + 同比环比 |
| **新闻面** | 近期公告、行业事件、监管、大额合同、管理层变动 | 事件 + 日期 + 出处 |
| **情绪面** | 分析师评级与目标价、社交讨论热度与倾向、机构持仓变化 | 倾向 + 依据，无数据就说无数据 |

每份报告结尾必须有 **「本报告的数据盲区」** 一节，列出没取到的关键数据。

### 第 2 步：多空辩论

用 Agent 工具起**两个研究员**，各自拿到四份报告全文：

- **看多研究员**：论证为什么这是机会。必须引用具体数字，禁止空泛看好。
- **看空研究员**：论证这笔投资最可能怎么亏钱。必须具体到"什么条件触发、亏多少"。

**默认 1 轮（各陈述一次 + 各反驳一次）**，用户要求深入时最多 3 轮。轮数上限是硬约束。

质量判据同 decision-panel：**双方必须在争夺同一份证据的解释权**，各说各话说明证据不足。

### 第 3 步：研究经理裁决

独立角色，不参与前面辩论。输出**投资论点（Investment Thesis）**：
- 采纳/不采纳多空各自核心论点的逐条理由
- 当前的核心矛盾是什么
- 决定性变量是什么（等什么明朗才能下结论）

### 第 4 步：交易员出方案

基于投资论点，给出可执行方案：方向（买/卖/持有）、理由摘要、
若行动则给出**分批区间、仓位上限、止损位、时间维度**。

### 第 5 步：三方风控轮辩

用 Agent 工具起三个风控角色，各自审视交易员方案：

- **激进派**：机会成本视角——过于保守会错过什么
- **保守派**：下行保护视角——最坏情况有多坏，防线够不够
- **中性派**：可执行性视角——方案自身有无逻辑矛盾、参数是否自相打架

中性派要**主动抓另外两方论证中的自相矛盾**（例如"反对宽止损却又要求把止损设在距现价 2% 处"——
这类矛盾正是原框架里最高价值的产出）。

### 第 6 步：组合经理拍板

最终裁决者，输出结构化结论：

```
【评级】买入 / 增持 / 持有 / 减持 / 卖出
【摘要】一段话说清结论和最关键的理由
【投资论点】逐条回应多空与三方风控的核心主张
【为何不是更激进的评级】
【为何不是更保守的评级】
【执行框架】加仓触发条件 / 减仓防线 / 仓位上限
【目标价与时间维度】
【决定性催化剂】盯什么事件
【数据盲区】本次分析缺了什么，因此结论在哪些方面不可靠
```

### 第 7 步：记账

写入 `~/Documents/ObsidianVault/笔记/学习/trading/<代码>-YYYY-MM-DD.md`，
并在同目录 `LEDGER.md` 追加一行索引：`| 日期 | 代码 | 评级 | 当时价 | 目标价 | 状态 |`。

状态初始为「待验证」。目录不存在就创建。

### 第 8 步：复盘（用户说"复盘"时触发）

1. 读 `LEDGER.md` 里所有「待验证」条目
2. 取当前真实价格，对照当初的评级和目标价
3. 更新状态（正确/错误/部分正确），写下**判断哪里对、哪里错、当时忽略了什么**
4. 教训写进 `~/Documents/ObsidianVault/笔记/学习/trading/LESSONS.md`
5. 分析同一标的时，先读该标的的历史台账和 LESSONS，把过往判断纳入上下文——
   这是原框架 `TradingMemoryLog` 的等价物，让判断跨次连续、可追责。

## 执行要求

- **并发**：四分析师一条消息内同时起；三方风控同理。串行会慢好几倍。
- **角色隔离**：分析师不下买卖结论，辩手不裁决，裁决者不辩论。合并角色 = 失去全部价值。
- **数据求真**：优先用可联网查证的实时数据。取不到就明说，不许用记忆里的旧数据装作最新。
- **中文输出**，术语首次出现带英文。
- **每次输出结尾固定加**：
  > ⚠️ 本分析仅为研究性质的推理过程演示，不构成投资建议。结论随模型与数据变化而变化，投资决策及风险由你自行承担。
